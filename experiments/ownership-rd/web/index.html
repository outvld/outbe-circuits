Реальные Groth16, Nova и Noir / UltraHonk в WebAssembly, в отдельном Web Worker. По умолчанию всё локально: сервер раздаёт файлы. Только при явном включении backend wrapping отправляются доказательство и public inputs, но не приватный witness.

Только исследовательский стенд

Примеры — публичные детерминированные fixtures: их приватные ключи известны. Groth16 использует экспериментальную одностороннюю trusted setup, а не производственную церемонию. Подпись Poseidon2 — новая, неаудированная и несовместимая с production. Не используйте реальные секреты или средства.

Параметры запуска

01 / CONFIG

Nova — система рекурсивных доказательств (IVC): здесь она последовательно объединяет ownership-шаги по слотам и завершает их доказательством Spartan IPA. Это не язык программирования и не EVM-формат Groth16.

Noir — язык и инструментарий описания схем, а не отдельная система доказательств. Здесь Noir ACVM вычисляет witness, а barretenberg (bb) создаёт и проверяет UltraHonk-доказательство локально. Доступны только восстановленные Canonical-схемы; экспериментальная Poseidon2-подпись поддерживается лишь Rust-движками Groth16 / Nova.

Настройки измерений

Flat aggregation проверяет ownership по слотам. Demo Tribute (full_proof) дополнительно проверяет 32 уровня Merkle inclusion и четыре public values: derived_owner, nft_hash, binding_hash, merkle_root; это не flat n=1.

Groth16 и Noir / UltraHonk доступны для обеих схем. Nova поддерживает только ownership-шаги Flat aggregation.

Groth16 поддерживает Canonical и экспериментальную Poseidon2-подпись для обеих схем. Noir / UltraHonk — только Canonical.

Доступные размеры берутся из manifest выбранного движка. Nova выполняет по одному ownership-шагу на слот; Noir использует отдельную схему для каждого размера.

Warm: сначала «Подготовить WASM», затем «Создать и проверить». Загрузка, SHA-256 и pk_decode выполняются при подготовке, а сессия сохраняется между сериями. Cold benchmark намеренно повторяет подготовку для каждого доказательства и не очищает HTTP/дисковый кэш. Прогрев не отбрасывается.

Опционально. Single-party unaudited trusted setup — не production. Backend загружает проверенные setup provenance, R1CS, proving key и VK один раз до готовности сервера. При включении опции startup-метрики появляются отдельно, ещё до proving. Backend реально проверяет UltraHonk внутри схемы и создаёт BN254 Groth16; отдельный verification call использует тот же resident VK. Cold / Warm управляют только CLIENT-сессией: для нового измерения startup перезапустите backend. Статический сервер без API не поддерживает wrapping. Отмена fetch прекращает ожидание клиентом, но уже начатая native computation завершается на сервере; до её завершения новый запрос получает busy (HTTP 409). Автоматических повторов нет. Локальная отмена по-прежнему останавливает Worker.

Большая схема: особенно 64 слота могут потребовать много памяти и времени. Мобильный браузер может закрыть Worker или вкладку без сообщения. Начните с 1 слота; отмена освобождает Worker, но не гарантирует немедленное освобождение памяти браузером.

Каждое наблюдение

03 / EVIDENCE

Без средних и медиан. Время этапов движка не включает первоначальную загрузку модулей, скачивание и SHA-256 артефактов. Nova «folding» включает синтез каждого шага; это не чистое время proving. Для Noir этап ACVM witness включает внутреннюю десериализацию программы, а verify — декодирование сохранённого VK. Сохранённый proving key для Noir не загружается: используется SRS.

Клиентская верификация выполняется после proving в той же сессии. Опциональный backend выполняет wrap и отдельный verify с resident ключами, без повторной загрузки setup в proving path. Startup отображается и экспортируется один раз на initialization ID; запросы ссылаются на него. Внешние wall-интервалы включают внутренние этапы: складывать их нельзя. Native process lifetime peak RSS — максимум за всю жизнь серверного процесса, не пик отдельного proof и не дельта; startup RSS — неизменный снимок этого максимума при готовности. Он показывается отдельно от ёмкостей WASM; native на настольном компьютере — не результат мобильного WASM. Compressed gnark Groth16 содержит commitment extensions: это не предполагаемые 128 байт и не стандартный EVM-формат.

Наблюдений пока нет. Каждый завершённый запуск останется доступен, даже если следующий будет отменён или завершится ошибкой.

Среда, память и запуск на телефоне

Все браузерные вычисления однопоточные. Число логических процессоров ниже — информация браузера, а не количество потоков proving.

Память WASM — ёмкость линейной памяти, измеренная до/после операций. У Groth16 / Nova это Rust-модуль; у Noir показывается сумма ёмкостей Rust fixture, Noir ACVM, Noir ABI и BB с отдельными снимками каждого модуля. Сразу после init измерен только Rust fixture, после загрузки Noir — все четыре модуля. Это не RSS, не физическая память и не пиковое потребление. Буферы JS и накладные расходы runtime/браузера в неё не входят. Браузер не предоставляет native RSS.

Как открыть на другом устройстве

Раздавайте весь каталог приложения как статические файлы по HTTPS; для модульных JS и WASM нужны корректные MIME-типы (text/javascript, application/wasm). Папки pkg/, vendor/ и assets/ должны находиться рядом с этой страницей. Noir не скачивает SRS из внешней сети: все runtime-артефакты берутся из локального manifest. SharedArrayBuffer не обязателен; при cross-origin isolation выбирается совместимый вариант BB WASM, вычисления остаются однопоточными.

На компьютере откройте http://localhost:8080, на телефоне в той же доверенной Wi-Fi сети — http://IP-компьютера:8080. SHA-256 выполняет сам WASM; для случайности используется криптографический getRandomValues, доступный в современных браузерах и без HTTPS. file:// не подходит. Если браузер блокирует API, используйте HTTPS. Firewall должен разрешать локальный доступ.

HTTP допустим здесь только для публичных тестовых fixtures, без реальных секретов: он не защищает загружаемый код и manifest от сетевой подмены. Для недоверенной сети используйте HTTPS. Длина и SHA-256 каждого артефакта проверяются перед использованием, но это согласованность с manifest, а не независимая подпись издателя.
